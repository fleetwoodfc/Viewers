# Implementation Plan: WorkItems List — Task Performer Actions

**Branch**: `002-workitems-task-performer` | **Date**: 2026-05-04 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `specs/002-workitems-task-performer/spec.md`

## Summary

Extend the existing OHIF WorkItems List screen with IHE RAD RRR-WF Task Performer actions: Claim (SCHEDULED → IN PROGRESS), Complete/Cancel (IN PROGRESS → COMPLETED/CANCELED), and Reject (send cancelrequest without claiming). A new `useWorkitemActions` hook encapsulates Transaction UID generation, state changes, and notification feedback. All UPS-RS operations delegate to the `DicomWebUpsDataSource` (feature 001). P3 adds a real-time WebSocket notification channel via `useUpsNotifications`.

## Technical Context

**Language/Version**: TypeScript 5.x / React 18.3.1
**Primary Dependencies**: `@ohif/ui-next` 3.13.0-beta.64, `@ohif/ui` 3.13.0-beta.64, `@ohif/core` 3.13.0-beta.64, Tailwind CSS 3.2.4, React Router v6
**Storage**: The SCU is the authoritative source of Transaction UIDs.  The SCP (e.g. dcm4chee-arc) treats the Transaction UID as an opaque lock token and does not reliably return it in `GET /workitems/{uid}` responses.  The client stores the UID in a session-scoped `useRef` map (hot path) and mirrors it to `sessionStorage` so it survives a page refresh within the same tab.  If neither cache has the UID (e.g. different tab, storage cleared), Complete/Cancel surface a descriptive error toast.
**Testing**: Jest + jsdom, `@testing-library/react`
**Target Platform**: Desktop web browser (OHIF Viewer web application)
**Project Type**: Web application feature (React component extension within monorepo)
**Performance Goals**: Claim/Complete/Cancel response reflected in list within 2 seconds (SC-002); no spinner visible >3s for successful claim (SC-001)
**Constraints**: Must not break existing WorkItemsList functionality (SC-006); no new packages may be added; all UPS-RS operations must go through the existing `DicomWebUpsDataSource`
**Scale/Scope**: Single route component (`WorkItemsList.tsx`), 4 new files, ~200–300 lines of new TypeScript
